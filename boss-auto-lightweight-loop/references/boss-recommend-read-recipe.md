# BOSS 推荐牛人页读取固定方案

## 定位

这个文档仅用于 `recommended_feed`。

目标是以最低 token 成本确认：

1. 当前是否已经进入推荐牛人页。
2. 当前页是否已经存在可读取的候选人卡片。
3. 当前卡片里哪些候选人属于本轮未处理对象。
4. 当前卡片里哪些候选人存在可绑定的“打招呼”按钮，供 `screen-and-greet` 优先消耗推荐页沟通额度。

## 读取原则

只要页面上已经稳定显示候选人卡片，就视为页面可读取。

此时必须：

1. 直接读取 DOM。
2. 直接提取候选人卡片文本和稳定标识。
3. 结合本地 state 判断哪些候选人属于本轮未处理。

不要默认：

- 等待 30 秒。
- 让用户确认页面是否加载完成。
- 让用户描述页面内容。
- 默认退回截图快照分析。
- 用“可能需要手动触发加载”作为第一判断。

## 固定主路径

1. 确认当前 target 已在 Boss 推荐牛人页；如果 `probe_reuse_enabled=true` 且当前仍在同一推荐牛人页上下文，可复用最近一次成功探针。
2. 用短 selector/短 eval 检查候选人卡片容器是否存在。
3. 用一次低成本 eval 统计：
   - 卡片数量。
   - 每张卡片的姓名、职位、期望、城市、标签和可见摘要。
   - 是否存在加载更多或继续滚动信号。
   - 卡片内打招呼按钮状态和可绑定标识。
4. 若卡片数量大于 0：
   - 直接进入候选人卡片提取。
   - 基于本地 state 过滤本轮未处理候选人。
   - 同一页连续卡片读取不要重复 `/targets` + `/info`，只在健康检查周期、滚动加载后或页面异常时重新探针。
   - 不要为每张卡片重新启动 web-access、重新连接 Chrome 或重新触发远程调试授权；候选人循环只做 DOM 读取、卡片绑定和按钮状态确认。
5. 若卡片数量等于 0：
   - 再做一次低成本 DOM 分层探针。
   - 只检查容器、iframe、懒加载占位、空列表文案、登录失效和风控信号。
6. 只有两轮 DOM 探针都无法确认页面状态时，才允许暂停。

## 低成本 DOM 探针

探针顺序固定为：

1. 页面标题和 URL 是否符合推荐牛人页。
2. 主内容容器是否存在。
3. 候选人卡片节点数量是否大于 0。
4. 是否存在“暂无结果 / 没有更多 / 加载中 / 请登录 / 风控验证 / 权益不足”之类文案。
5. 是否存在 iframe，且候选人内容是否实际在 iframe 内。

探针输出必须优先结构化，例如：

```json
{
  "source": "recommended_feed",
  "is_candidate_page": true,
  "card_count": 12,
  "has_load_more": false,
  "empty_state": false,
  "risk_prompt": false
}
```

不要输出大段泛化推测。

## 增量读取规则

只有在页面明确存在下面信号之一时，才继续增量读取：

- “加载更多”按钮。
- 继续滚动后出现新增卡片。
- 容器滚动高度继续增长。

如果没有这些明确信号，就把当前已显示卡片视为本轮可直接处理集合。

## 未处理判断

推荐牛人页不要假设有稳定“未读/未处理”原生标记。

本轮未处理判断默认主要依赖本地 state：

- 本地无处理记录。
- 本地状态是 `discovered`。
- 本地状态是 `eligible`。
- 本地状态是 `screened` 但尚未触达。
- 上一轮只有 `last_observation` 失败记录但尚未触达。

默认跳过：

- `first_contact_sent`。
- `attachment_requested` 及以后状态。
- `boss_completed`。
- 明确重复或硬过滤不通过的候选人。

## 额度消耗读取顺序

`screen-and-greet` 中的推荐页读取服务于“先把推荐页额度耗尽”的阶段：

1. 读取当前已渲染卡片。
2. 过滤本地 state 中已触达、已完成、重复或不可唯一绑定的候选人。
3. 对仍有可点击“打招呼”按钮的卡片逐个交给 `boss-greet-recipe.md`。
4. 当前屏处理完后，只有在存在加载更多、滚动后新增卡片或容器滚动高度增长时，才继续受控滚动读取下一批。
5. 如果没有新增可打招呼候选人、列表到底、或捕获推荐牛人沟通额度耗尽信号，则结束推荐页阶段。

推荐页读取阶段不打开详情做 JD 筛选，不等待聊天页未读信号，也不因 `max_greet_per_run` 达到而停止。

## 暂停条件

只有在下面任一情况出现时，才允许暂停并请求用户帮助：

1. DOM 两轮探针后仍无法判断页面状态。
2. 明确出现登录失效、验证码、风控验证。
3. 明确出现空列表，但与用户实际任务目标明显矛盾。

暂停时要说明：

- 当前停在“卡片页 DOM 无法确认”。
- 已完成的探针结果是什么。
- 下一步最小恢复动作是什么。

不要要求用户重新描述完整页面内容。
